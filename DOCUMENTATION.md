## 1. What this is

A one-page, fully responsive portfolio that reads as **a designer who builds**: visual craft
leads, and the fact that she ships the code herself is the edge.

The audience is recruiters and internship leads. The single job of the page is to make
"she designs it and then ships it" undeniable in one scroll.

### Locked decisions

| Decision | Choice | Why |
|---|---|---|
| Message | Designer who builds | Visual work leads, code is the differentiator |
| Typeface | Space Grotesk alone, Space Mono for annotations | One family is the most minimalist answer; hierarchy comes from weight |
| Ground | `#16131F` violet-charcoal | Not black. Same hue family as the accent, so the violet belongs to the page |
| Themes | Light and dark, user toggle, dark default | A stranger opens this on an unknown device |
| Accent | Violet, split by job (see §3) | Her favourite colour, held to AA |
| Components | shadcn/ui on Radix | Requested. Aliased onto our tokens, never default-styled |
| Signature | Inspect mode | The page reveals its own construction |
| Certificates | 3D tilt grid, 1.91:1 cards | All 23 source images are an identical 1772x928 |
| Hosting | Vercel free tier, static | Free, no cold starts, custom domain |

### What was deliberately dropped

**Laravel.** Vercel cannot run it without an unofficial PHP runtime, an external database,
and a read-only filesystem to work around. For a page updated a few times a year, a backend
buys nothing. Laravel stays visible as a featured project and in the toolkit. If the site
ever moves to Laravel, `src/data/` ports to Eloquent models almost line for line.

**Base UI.** Was chosen for the lightbox before shadcn was requested. shadcn's dialog is
Radix, and shipping two dialog primitives is exactly the library-mixing that gets flagged.
Removed.

## 2. Architecture

```
assets/            Source archive. NEVER modified by the build.
  certificates/    23 jpegs @ 1772x928 + certificate_links.txt
  creative_projects/  11 pngs, mixed orientation
  lj_profile.jpg
public/            GENERATED by `npm run images`. Safe to delete and rebuild.
scripts/           Build tooling
src/
  data/            The content seam. Typed. Nothing hardcoded in components.
  components/ui/   shadcn components + our own
  hooks/           useTheme, and later useInspectMode / useReveal / useTilt
  styles/globals.css  The entire token layer
  lib/utils.ts     cn() - clsx + tailwind-merge
```

### Commands

| Command | Does |
|---|---|
| `npm run dev` | Dev server on :5173 |
| `npm run build` | Typecheck then production build |
| `npm run typecheck` | Types only |
| `npm run images` | Rebuild `public/` from `assets/` |
| `npm run certs` | Regenerate `src/data/certificates.ts` from `certificate_links.txt` |

### The data seam

Every section reads from typed arrays in `src/data/`. Adding a project is editing one array
entry, not touching a component. `src/data/types.ts` is the contract.

`certificates.ts` and `design.ts` are **generated** - edit the source
(`certificate_links.txt`, or the title maps in the scripts) and re-run, don't hand-edit.

## 3. The token layer

All colour lives in `src/styles/globals.css`. Components read tokens, never raw hex.

### The violet splits by job

This is the least obvious decision in the codebase, so it is worth understanding.

The original single violet `#8B5CF6` measured **4.23:1 under white button text**, below the
4.5:1 AA minimum. It looked completely fine; only measuring caught it.

The cause is structural. On a dark ground, **no single violet can do both jobs**:

- Dark enough for white button text, and it fails as a link colour on the canvas
- Light enough to read as a link, and it fails under white text

So:

| Token | Job | Dark | Light |
|---|---|---|---|
| `--mark` | Violet as **text** (links, annotations) | `#A78CE8` | `#7343CC` |
| `--mark-solid` | Violet as a **surface** (buttons) | `#7343CC` | `#7343CC` |

Light mode needs only one value because both jobs pass there.

Every pair now clears AA in both themes, lowest 5.91:1. The revised values also dropped
saturation from 90% to 57-67%, which moves the accent out of the "AI purple" register.

`::selection` uses `--canvas` as its text colour, not `--on-mark`, because on dark `--mark`
is the *light* violet and white on it would fail.

### shadcn is aliased, not parallel

shadcn ships its own vocabulary (`--background`, `--primary`, `--muted`). Rather than
maintaining two palettes, every shadcn name is an **alias** onto our semantic tokens,
declared once - `var()` resolves at use time, so they inherit the theme swap for free.

Verified: `shadcn fg on bg` measures 15.42, identical to `type on canvas`. Change `--canvas`
and every shadcn component follows.

### Theming has no flash

A **blocking inline script** in `index.html` resolves the theme before any stylesheet and
before first paint. It must stay inline, synchronous, and first in `<head>`. Making it
external, deferring it, or moving it below the font links reintroduces the white flash it
exists to prevent.

`useTheme` follows the OS until the visitor states a preference; after that, their choice
wins until they change it.

## 4. Motion rules

Three skills govern motion and they disagree, so the resolution is written down:

`animate` is Emil Kowalski's lens - restraint, sub-300ms. `design-motion-principles` weights
that lens by project type, and for a **creative portfolio** it puts Emil in the *selective*
slot with Jakub Krehel (200-500ms polish) primary. Its instruction is explicit: *"Do not
universally flag or cap durations."*

So durations are **tiered by frequency**, not capped flat:

| Tier | Seen | Budget |
|---|---|---|
| 1 | Once per visit (hero sequence, timeline draw) | Expressive, can exceed 500ms |
| 2 | Occasional (lightbox, filters, reveals) | 200-500ms |
| 3 | Frequent (hover, press, toggles) | Under 200ms |

**Hard constraints** carried from the anti-slop checklist:

- Stagger exactly **once** on the page (the certificate grid)
- Hover-scale exactly **once** (project images)
- **No pulsing anything** - no breathing "available for work" dot
- **No bounce** on utility actions (lightbox, toggles, nav)
- Only **three** sections get an entrance, each different. Body copy never animates in.
- Easing tokens deliberately override Tailwind's weak `ease-out` / `ease-in-out`

## 5. Asset pipeline

`assets/` is the archive and is never touched. `public/` is generated.

**Measured: 43.3 MB of source becomes 4.3 MB of WebP, 90% smaller.**

`fit: 'inside'` means nothing is ever cropped or squared off. Design pieces keep their
natural proportions - the real set is 7 landscape, 2 portrait, 2 square, and that mix *is*
the Archive composition.

Certificates get two variants: a 900px grid thumbnail (~15 KB) and a 1600px lightbox image
(~42 KB), so the grid loads cheaply and the lightbox is sharp.

Intrinsic `width`/`height` ship on every `<img>` to hold CLS at zero.

**One counter-intuitive case:** the profile photo is already an aggressively compressed
JPEG, so encoding it at high WebP quality produced a *larger* file than the source. Capped
at 1000px / q78 instead.

## 6. Tooling

**14 skills** in `.agents/skills/` plus **Playwright MCP** at user scope.

Playwright is the most valuable of them and it is not a design rule: it lets the page be
*looked at* rather than guessed about. Contrast is measured, not eyeballed; horizontal
overflow is asserted, not spotted. It caught the violet AA failure that six rounds of design
rules did not.

Verification runs at **4 widths x 2 themes**, because light mode is where borders vanish and
contrast quietly fails.

### 2026-08-21 - Navbar rewrite, merged landing, image-first design grid

**Navbar was rebuilt.** The first version keyed off scroll *direction*, so it only became a
bar while scrolling up and snapped back the moment it reached the top. Wrong behaviour. It is
now keyed off *position*: pill near the landing, bar once past 60% of the viewport height,
and it stays a bar however far down you go.

An intermediate attempt used an IntersectionObserver on a zero-height sentinel at the bottom
of the landing. **That silently fails**, and it is worth recording why: an element that moves
from below the viewport to above it in one frame never changes `isIntersecting`, so no
callback fires and the nav stays stuck. A position threshold cannot miss. The listener is
passive and rAF-batched.

- **Hero and About merged** into one `Landing`: photo, name, thesis, about copy, social
  links. Two sections both introducing her was one too many. The "23 certificates,
  11 design pieces" line is gone.
- **Design grid is now image-first.** Titles removed from the cards; hovering dims the piece
  and reveals its title and medium. The work reads as a gallery rather than labelled cards.
  Also reachable by keyboard via `group-focus-visible`.
- `scroll-mt-20` on every section, so anchor jumps clear the sticky bar instead of parking
  headings underneath it.

### 2026-08-21 - Landing layout, design hover, profile pipeline

- Landing is now **photo left, text right**. The thesis line was removed.
- Profile photo has **square corners** by request, and a faint shadow.
- Design pieces carry a **soft shadow** (`--shadow-soft`), and on hover they
  **zoom 2.5% with a 0.7deg tilt**, lift to `--shadow-lift`, and raise `z-10` so the
  lifted card sits above its neighbours instead of being clipped. This is the page's one
  sanctioned hover-scale. `motion-reduce:transform-none` opts out.

**Profile photo: a compression lesson worth keeping.**

The re-uploaded source arrived as `lj_profile.png` rather than `.jpg`, so the pipeline's
matcher was widened to accept either.

The source has a **halftone filter baked in**, which is the worst case for two separate
reasons. A regular dot grid is high-frequency, so it resists lossy compression: 1200px/q82
landed at 566 KB and extra `effort` barely helped. And downscaling a dot grid makes it
interfere with the pixel grid, so at 1000px scaled into a 320px frame it turned to moire mud.

Fix was to stop fighting it and serve near the rendered size: **640px at q80, 233 KB**. At a
320px CSS frame on a 2x display that is a 1:1 device-pixel match, so the halftone renders as
the intentional grain it is rather than as interference. Verified via `naturalWidth` against
`getBoundingClientRect`, not by eye.
